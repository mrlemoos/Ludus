# Domain docs

This repo uses a single-context layout.

## Before exploring

Read root `GLOSSARY.md` and relevant decisions in `docs/adr/`.

If these do not exist, proceed silently. Create them only when
domain work resolves terminology or architectural decisions.

## Vocabulary

Use glossary terms consistently in issues, proposals and code.
If a term is missing, reconsider it or flag the gap for
domain modelling.

## Decisions

If a proposal contradicts an ADR, identify the ADR and explain
why the decision should be reconsidered.
